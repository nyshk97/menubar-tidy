# 隠さずに、溢れた項目を一覧から開く作りへの入れ替え

## 概要・やりたいこと

MenuBar Tidyは動作が安定せず、macOSのアップデートでも壊れる。upstreamのThawもmacOS 27でissueが噴出している（#1367 配置を覚えない、#1322 勝手に別セクションへ移る、#1314、#1333 動かせない）。

解決したい問題は「表示したいアイコンが多く、ノッチの裏などに隠れた項目をクリックする方法がない」こと。不安定さの本体は画面収録ではなく、**項目をプログラムで動かす仕組み**（偽装⌘ドラッグ・位置からのセクション推測・非公開API）にある。

そこで、Thaw由来のコードを小さな新しい実装に入れ替える。

- **隠さない**: 仕切りによる押し出しをやめ、溢れさせるのはmacOSに任せる
- **開く**: 自分のアイコンをクリック → ドロップダウンのメニューに全項目（アプリのアイコン＋名前）→ 選んだ項目にAXPressを送る
- **権限**: アクセシビリティだけ。画面収録・項目の移動・非公開API・XPCヘルパーは使わない
- **引き継ぐもの**: バンドルIDと署名（アクセシビリティの許可が引き継がれる）、Sparkle・Homebrewの配布経路、dev版の分離
- **バージョン**: 2.0.0

アイコンが増える・画面が13インチになる・ノッチが広がる、といった将来の変化にも、一覧に並ぶ数が増えるだけで耐えられる（下の検証結果を参照）。

## 前提・わかっていること

### 決定事項（/dig-lite）

| 論点 | 決定 |
|---|---|
| 作り方 | このリポジトリの中身を入れ替える。名前・バンドルID（`com.nyshk97.MenuBarTidy` / dev版 `.dev`）・署名・Sparkle・Homebrew caskはそのまま |
| 隠す仕組み | 無し。仕切り（`Thaw.ControlItem.Hidden` / `AlwaysHidden`）を作らない。並び順は自分で⌘ドラッグする（よく使うものを右へ） |
| 開き方 | 自分のアイコンをクリックするだけ。空きスペースのクリック・ショートカットは作らない。アイコンは右端に⌘ドラッグで置いておく前提（左に置くと自分自身が溢れる） |
| 一覧の形 | macOS標準のドロップダウンのメニュー（`NSMenu`）。メニューバーの並び順（左→右）で、「隠れている」「見えている」の2つに区切る。末尾に「アップデートを確認…」「終了」 |
| アイコン | アプリのアイコン（`NSRunningApplication.icon`）。コントロールセンターの項目はSF Symbolsで描く（本物のグリフは画面収録なしでは取れない） |
| 開く方法 | AXPressだけ。開けない項目への代わりの手段（偽装クリック・一時移動）は作らない |
| AXPressで開けない項目 | TodoMacはtodo-app側で直す（Phase 4）。Spotlightは⌘Spaceで代用 |
| 項目の間隔 | `NSStatusItemSpacing = 6`を`~/Dropbox/settings/setup-defaults.sh`に入れる（溢れる数を減らすため。アプリからは書き込まない） |
| 名前 | 「MenuBar Tidy」のまま（表示名は後から変えられる） |

- 2枚のときの基準: 成功の基準は、**自分のアイコンをクリックした画面（一覧が出た画面）**に項目のメニューが開くこと（1回目で決定）。「隠れている」の判定には、項目の座標がある画面（AXが返すアクティブなメニューバーの画面）を使う（ログ >方針変更）
- TodoMacの修正（Phase 4）は2.0.0のリリースの前提にしない。直るまではTodoMacを溢れない右側に置いておく（1回目で決定）
- 作業は`rewrite/item-list-menu`ブランチで行い、Phase 2が終わってからmainに入れる（途中でも1.0.xの修正版を出せるように）
- コントロールセンター以外のApple製プロセス（TextInputMenuAgent等）は、アプリ名でなく`AXDescription`を表示名に使う
- 会社貸与PC（`TsubasanoMacBook-Pro`）では、このセッションから署名付きのビルドをしない（署名鍵がキーチェーンにあるため）。自分で回すビルド・テストは`CODE_SIGNING_ALLOWED=NO`で回し、AXまわりは本体のソースを組み込んだコマンドをターミナルから動かして確かめる。署名したdev版の起動確認は人間が自分のターミナルで`mise run run`して行う

### 検証で確定したこと（2026-10-20、macOS 26.6.2、MacBook Pro 14" Mac16,8、内蔵ディスプレイのみ）

**項目の列挙**
- 各アプリの`AXExtrasMenuBar`の子要素から、全項目の持ち主のアプリ・座標・AXPressが取れる。ウィンドウ一覧（CG）では他社の項目がすべて「コントロールセンターの`Item-0`」に見える（macOS 26の仕様）ので、CGは使わない
- コントロールセンターの項目は`AXIdentifier`が`com.apple.menuextra.{battery,wifi,bluetooth,now-playing,controlcenter,clock}`で、SF Symbolsの対応付けに使える。他社の項目は`AXIdentifier`無し、`AXDescription`はアプリ名・空・SF Symbol名（Translatorは`character.bubble.fill`）とまちまち
- 一覧から外すもの: コントロールセンターの`0×0`・`AXEnabled=false`の項目（14個）、`x=-1`の項目（Karabiner-Menu、Microsoft Defender Helper。何を意味するかはPhase 0で確かめる）
- 全87アプリを`AXUIElementSetMessagingTimeout(0.2)`で走査すると**1.93秒**かかる → メニューを開く処理の中で（同期で）全走査するのは不可。項目を持つpidをキャッシュする

**AXPressとメニューの位置**
- メニューは**項目のいる位置の真下**に開く
- 仕切りで画面外（x≈-4000）に押し出した項目: 15個中13個は画面外に開き、TodoMacとSpotlightは何も開かない
- 開いたメニューの位置はAXから変えられない（`AXPosition`は`settable=false`、セットしても位置不変）
- **macOSが自然に溢れさせた項目は、右から隙間なく並べられ、画面内の座標（ノッチの裏・アプリのメニューの下）に置かれる**。AXPressでメニューが真下に開いて見える
  - ノッチの裏: バッテリー（x=664）・Wi‑Fi（706）・Pecha（743）・Memode（811）→ 4個とも開いて見えた
  - 仮アイコンでさらに溢れさせた場合: x=495・x=47 → 開いて見えた / x=-177 → 画面外に開いて見えない
  - **限界は「全項目の幅の合計 ≤ 画面の横幅」**。このMacは1512pt（13インチのAirは1470pt）、今の合計は約860pt
- メニュー型（`NSStatusItem.menu`）の項目にAXPressを送ると、メニュー表示中は呼び出しが戻らず、タイムアウトで`kAXErrorCannotComplete`（-25204）が返る。メニューは開いたまま → **メインスレッドで呼ばない・-25204を失敗扱いしない**
- 「開いて見える」の判定はメニューのウィンドウの座標による（Claude CodeのBashからは`screencapture`が真っ黒になるため）

**幅の数字**
- ノッチより右で項目を置けるのは664pt（`NSScreen.auxiliaryTopRightArea`）。ノッチは664〜848
- アプリのメニューの右端（AXの`AXMenuBar`の子要素）: Chrome 646、Nemo 477、ターミナル 410、Finder 448。スクリプトエディタは915でノッチの右まではみ出す
- `NSStatusItemSpacing`だけが項目の幅に効く（既定16→6で1個あたり−10pt）。`NSStatusItemSelectionPadding`は幅を変えない。`-currentHost`でMacごとに保存され、各アプリは起動時に読む

**コードベース**
- `Thaw.xcodeproj`は`PBXFileSystemSynchronizedRootGroup`（6個）なので、ファイルはディスクから消せばビルド対象から外れる。ターゲット（`MenuBarItemService`）とSPMパッケージの削除はpbxprojの編集が要る
- `scripts/release.sh`はpbxprojの`MARKETING_VERSION` / `CURRENT_PROJECT_VERSION`を`sed`で書き換える。`scripts/make-release-zip.sh`は`MenuBarItemService.xpc`を名指しで署名・検証している
- 自分のアイコンの保存名は`Thaw.ControlItem.Visible`（`NSStatusItem.autosaveName`）。**同じ名前を使えば今の位置（右端寄り）を引き継げる**
- ログイン項目は`LaunchAtLogin`（`AppDelegate.swift:133`）。dev版は起動時に自分の登録を外す
- 旧版のキャッシュは`~/Library/Caches/com.nyshk97.MenuBarTidy`が1.0MB、Application Supportは空。残しても害はない
- 項目を動かさないので、常用版とdev版を同時に起動しても取り合いにならない（VERIFY.mdの「2つ同時に動かさない」は不要になる）
- 検証に使ったスクリプトは`/tmp/axspike/`にある（消える場所。Phase 0でリポジトリに移す）

### やらないこと
仕切り・隠す機能、レイアウト編集画面、プロファイル、Thaw Bar、画面収録、項目の移動、`MenuBarItemService`（XPC）、空きスペースのクリック、ショートカット、AXPressで開けない項目への代わりの手段、間隔のアプリからの書き込み、AXPressが-25204を返したときに相手が応答しているかのログ

## ログ
